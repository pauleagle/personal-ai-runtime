# Completion Check

## 目的

Completion Check 是 agent 在完成任務後，用來依成功標準檢查結果、回報驗證狀態與指出殘餘風險的收尾流程。

它的目標是避免任務看似完成但未被檢查、測試未執行、成功標準未逐項確認，或仍有問題卻沒有明確告知使用者。

## 核心原則

完成任務不只代表已經修改檔案，也代表 agent 已檢查結果是否符合要求。

完成後，agent 應說明：

- 做了哪些變更
- 哪些成功標準已確認
- 使用了哪些驗證方式
- 哪些驗證無法執行
- 哪些地方仍可能有問題
- 是否有建議的後續動作

## 適用時機

- 任務包含檔案修改、程式碼修改、文件整理或流程更新
- 使用者有明確成功標準或檢查條件
- 任務影響多個檔案、格式、版本或公開行為
- 執行過測試、validator、lint、搜尋或人工比對
- 有部分驗證無法執行，需要誠實回報

## 不適用時機

- 單純回答問題，沒有產出或修改
- 使用者只要求快速草稿，不要求驗證
- 任務仍在中途，尚未完成
- 使用者要求暫停或只要狀態更新

## 檢查項目

完成任務後，agent 應逐項確認：

1. 是否完成使用者明確要求的項目
2. 是否沒有加入未要求的功能或範圍外修改
3. 是否保留既有風格、格式、例子與判斷
4. 是否已執行可用的測試、validator、lint 或搜尋檢查
5. 是否有無法執行的驗證需要說明
6. 是否有殘餘風險或仍可能有問題的地方
7. 是否需要更新索引、README、狀態表或相關文件

## Agent 行為規則

agent 不應只說「完成了」，而應說明完成的依據。

若使用者提供成功標準，agent 應依該標準逐項檢查。

若使用者沒有提供明確成功標準，agent 應根據任務內容列出合理的檢查項目。

若驗證失敗，agent 應說明失敗原因、已採取的修正，以及仍未解決的地方。

若驗證無法執行，agent 應明確說明沒有執行，而不是暗示已確認。

## 標準 Prompt

完成後請執行 completion check。

請根據本次任務的成功標準逐項檢查結果，說明你做了哪些驗證，哪些驗證無法執行，並指出仍然可能有問題的地方。

## 建議輸出格式

### Completed Work

本次完成的工作：

- ...

### Success Criteria Check

成功標準檢查：

- ...

### Validation

已執行的驗證：

- ...

### Not Verified

未能驗證的項目：

- ...

### Remaining Risks

仍可能有問題的地方：

- ...

### Follow-Up

建議後續：

- ...
