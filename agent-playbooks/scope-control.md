# Scope Control

## 目的

Scope Control 是 agent 在執行任務期間用來避免任務擴張、過度修改與未要求功能的控制流程。

它的目標是確保 agent 優先使用最簡單的方法完成使用者指定的範圍，並保留既有風格、例子與判斷。

## 核心原則

agent 不應把「可以順手做」當成「應該做」。

執行任務時，agent 應優先遵守：

- 使用最簡單可行的方法完成目標
- 不加入使用者未要求的功能
- 不擴大修改範圍
- 保留既有架構、語氣、格式、例子與判斷
- 只在必要時增加新抽象或新規則
- 遇到可能改變任務範圍的選擇時，先詢問使用者

## 適用時機

- 任務需要修改檔案、文件、程式碼或流程規格
- 使用者指定了明確修改範圍
- 任務容易被 agent 擴張成重構、重新設計或額外功能
- 既有文件或程式碼已有明確風格與慣例
- 需要在多種解法中選擇最小、最直接的方式

## 不適用時機

- 使用者明確要求全面重構、重新設計或擴充功能
- 使用者要求提出多種方案，而不是直接執行
- 既有內容已不可維護，且使用者授權重新整理
- 安全性、資料遺失或重大錯誤需要超出原範圍處理

## 工作流程

1. 確認使用者指定的任務範圍
2. 判斷哪些檔案、段落或行為屬於範圍內
3. 判斷哪些可能是範圍外但容易被順手修改的內容
4. 選擇最簡單且足以完成目標的方法
5. 優先沿用既有風格、命名、格式與結構
6. 避免加入未要求的功能、抽象、重構或文件段落
7. 若必須超出範圍，先說明原因並詢問使用者

## Agent 行為規則

agent 在執行中應持續檢查：

1. 目前修改是否仍在使用者指定範圍內
2. 是否加入了使用者沒有要求的功能或規則
3. 是否能用更小的修改達成同樣目標
4. 是否保留了既有風格、例子和判斷
5. 是否有範圍外問題需要另外回報，而不是直接修改

若發現範圍外問題，agent 應先回報或列為後續建議，不應直接納入本次修改。

若使用者要求「順便整理」、「幫我優化」等模糊指令，agent 應先界定整理範圍，再開始修改。

## 標準 Prompt

請在執行這個任務時套用 scope control。

請優先使用最簡單的方法完成我指定的範圍，不要加入未要求的功能，不要擴大修改範圍，並保留原本的風格、例子和判斷。

如果你發現需要超出範圍才能完成，請先說明原因並詢問我。
